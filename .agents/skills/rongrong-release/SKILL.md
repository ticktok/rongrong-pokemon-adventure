# 发布与存档保护

用户已要求每个完整功能修改任务执行到正式上线。沿用当前任务的认证与工具完成全流程，不把云端管理密钥搬到 GitHub。GitHub Actions 负责检查，当前任务负责合并、部署、验证和 Release。明确要求仅本地或暂不发布时遵循当次要求。

## 发布前

1. 读取项目 AGENTS.md、docs/DEPLOYMENT.md、cloudbaserc.json 和 deployment.json，核实 Git 分支、远端、线上最新 Release 和资源状态。只使用当前项目环境，不改变其他环境或套餐。
2. 使用 codex/ 功能分支。修复/视觉调整升 patch，新增功能/内容升 minor；重大不兼容修改需单独明确。版本唯一来源是 package.json，同步 lockfile、CHANGELOG 并构建；构建会生成界面、SW 缓存和函数包版本。
3. 执行 npm run typecheck、npm test、npm run build，以及 npm run verify:saves -- --ref <上次已部署标签>。最后一条只读真实存档，并从 Git 读取上一版内容，检查 ID 未被删除或重新指派；不另建冻结文件或 hash。内容名称的合法变更也应解释其兼容性，必要时写明确迁移和测试，不用跳过检查掩盖错位。
4. UI 修改实际验证涉及的页面和屏幕尺寸。正式家庭仅查看与导出，不点击领取、选伙伴、对战等写操作。QA 写操作必须先备份并在结束后恢复；不得把生产存档复制进公开测试文件。
5. 检查待提交文件与 dist 不含 private、凭据和家庭资料。提交、推送并创建 PR，附上实际验证结果；使用 Codex attach_artifact 关联 PR。CI 成功且无未处理问题后合并，不强推，不因私有仓库缺少分支保护而购买套餐或公开仓库。

## 部署与发布

1. 切到合并后的 main 并核对提交，重新构建。从该提交部署，未提交代码不得混入发布。
2. 运行 npm run backup -- --reason release。确认本地文件、云端对象及读回验证成功。备份失败停止部署。首次安装备份设施先用原只读导出保存本地存档，再增量迁移、建立私有桶和备份函数，完成首次云端备份。
3. 数据库仅执行本次必要的增量迁移，先 dry-run。保留 rr_commit 的服务端鉴权、事务、revision 和 operationId 去重。普通内容扩展不重置存档。未来变更 schemaVersion 必须提供保留字段的迁移、旧存档和并发测试。
4. 只部署有变更的函数；已有函数只更新代码以保留密钥与权限。新备份函数无公开路由，客户端调用必须被拒绝。部署 Web 使用 npm run deploy:web，仅上传 dist。超时先查状态，再决定重试。
5. 完成实际线上登录、资源、旧存档、受影响功能验证；再次执行兼容检查。读取发布前后正式家庭存档：revision 不变时内容应一致；revision 增加时核对正常操作与跨日处理，不能覆盖为旧快照。
6. 线上验证失败时不创建成功 Release；按文档回滚应用版本，保留新进度。数据恢复必须另获对目标家庭和具体备份的明确授权。
7. 验证成功后，给合并提交打 vX.Y.Z 标签并推送，创建正式 GitHub Release（不标 prerelease）。把网站、Git 提交、云端应用/函数版本、迁移版本、备份与验证结果写入非敏感部署回执，作为 Release 附件；报告网站、PR、Release 链接。不要提交含家庭 ID、账号或备份下载地址的回执。

## 备份与恢复

- 云端每日 Asia/Shanghai 03:00 备份；发布前另备份。桶为私有，只有服务端可访问。独立对象持续保留，不自动删除。
- 备份覆盖 rr_saves、rr_members、rr_operations 的同一 MVCC 快照。上传成功不等于备份成功，必须下载、解压、校验结构并比较完整内容。
- 查看近期备份函数日志中的 backup_verified 记录；有失败或每日备份超过 26 小时未成功时先定位原因，不声称备份正常。
- npm run backup:verify -- --file <本地备份> 或 --key <云端对象> 可验证备份。
- npm run backup:restore -- --file <文件> --family <精确家庭ID> 默认只预览。经明确授权才加入 --apply --revision <预览返回的当前revision>。先生成安全备份，再由 rr_commit 检查并发；不回退账号映射和操作日志。冲突需重新预览，不盲目重试。
- 完成恢复后读回并核对伙伴、图鉴、队伍、词汇、奖励及未完成操作。一次明确授权的 QA 恢复演练可以执行；不得把它扩展为正式家庭恢复授权。
